# Ring and ERA5 dual-reference validation

This is an additive fixed-protocol validation. It does not overwrite historical
Ring/ERA5 evidence or change baseline code. The candidate is centroid-reference
Dual RA with rho=.5, not the earlier extremum-reference Ring revision.

From the repository root (installed project environment):

```sh
mkdir -p results/dual_public
.venv/bin/python experiments/dual_reference/public_data.py > results/dual_public/execution.txt 2>&1
.venv/bin/python experiments/dual_reference/public_report.py
.venv/bin/python experiments/dual_reference/public_report.py --verify
```

Use `--dataset ring` or `--dataset era5` for an individual numerical run. The
combined report requires both completed datasets. `--plot-only` redraws from
saved maps and freshly checked matching input centroids without rerunning solvers.

ERA5 requires `data/real/ERA5_MSLP/ERA5_MSLP_19991117_20000114.nc`. Its complete
SHA256 and metadata are recorded in the output protocol. Ring is generated by
the locally archived author code version. Neither is claimed to be a byte-exact
reproduction of every input/preprocessing choice in both papers.

Outputs are in `results/dual_public/{ring,era5}`. Metrics include per-axis
SNS/TW(k=3)/TD, median end-to-end runtime over three cyclic-order repetitions,
2D position/motion/direction, original 2D distance stress, width growth, tau,
actual raster size, pixel metrics, and matching robustness. Dual runtime counts
both solvers. Single-view 2D metrics explicitly use a birth-Y oracle or a separate
first-frame affine decoder; they are not native baseline 2D reconstructions.

Reports and figures: `docs/PUBLIC_DATA_DUAL_REPORT.md`,
`results/dual_public/performance_summary.*`, and each dataset's
`input_fields.*`, `comparison_maps.*`, `longest_tracks.*` (PNG/SVG/PDF).
The report script independently audits all stored constraints and compares
baseline anchors to the historical Ring/ERA5 records, then writes a scoped
manifest. Local regenerable .npz files are excluded from Git.
